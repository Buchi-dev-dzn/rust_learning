# 第17章 ターミナルの仕組みと ANSI エスケープシーケンス

## この章のゴール

- 端末エミュレータ・tty・pty・シェル・プログラムの関係を説明できる
- ESC (`\x1b`) と CSI (`ESC [`) で始まるエスケープシーケンスの形を読める
- カーソル移動・画面消去・色 (16 色 / 256 色 / truecolor)・装飾を出力できる
- 代替スクリーン (alternate screen) とカーソル非表示の意味を知る
- エスケープシーケンスを組み立てる関数を書き、文字列としてテストできる

ライブラリ (crossterm / ratatui) が裏でやっていることは、結局この章のバイト列を
stdout に書くことです。ここを理解すると、ライブラリなしでも TUI が書けるようになります。

## ターミナルはどう動いているか

昔の「端末」は、シリアル線でコンピュータにつながった物理的な機械 (VT100 など) でした。
キーを押すとバイトが送られ、コンピュータから届いたバイトを画面に表示するだけの装置です。
いま使っている iTerm2・Terminal.app・GNOME Terminal・Windows Terminal などは、それを
ソフトウェアで真似る **端末エミュレータ** です。

```
┌────────────────┐   キー入力のバイト   ┌─────────────┐   stdin   ┌───────────┐
│ 端末エミュレータ │ ───────────────▶ │ pty (master)│ ───────▶ │  シェル /   │
│ (iTerm2 など)   │ ◀─────────────── │  ⇅ カーネル │ ◀─────── │ あなたのアプリ│
└────────────────┘   表示するバイト    │ pty (slave) │  stdout   └───────────┘
                                      └─────────────┘
```

- **tty** … 端末デバイスの総称 (teletypewriter の略)。`tty` コマンドで `/dev/ttys003` などと表示される
- **pty (疑似端末)** … カーネルが提供する、master/slave の 2 つの端を持つ仮想の端末デバイス。
  端末エミュレータは master 側を持ち、シェルやアプリは slave 側を stdin/stdout/stderr として使う
- **line discipline** … pty の中にあるカーネルの処理層。行編集 (Backspace)・エコー・`Ctrl-C` → SIGINT
  などを担当する。第18章の raw モードは、これを無効にする話

アプリから見ると、端末は「stdout に書いたバイトが画面に出る」「キーを押すと stdin にバイトが来る」
だけの存在です。ただし書いたバイトの中に **特別な並び** があると、端末エミュレータはそれを
文字としてではなく **命令** として解釈します。それがエスケープシーケンスです。

## エスケープシーケンスの形

ESC 文字 (コード 27 = `0x1b`) で始まるバイト列です。Rust では `"\x1b"` または `"\u{1b}"` と書きます。
(ドキュメントでは `ESC` や `^[` と表記されることもあります。)

よく使うのは **CSI (Control Sequence Introducer)** = `ESC [` で始まる形です。

```
ESC [ <引数> ; <引数> ... <終端文字>
\x1b[  10   ;   5            H        ← 10 行 5 列へカーソル移動
```

- 引数は 10 進数をセミコロン区切り (省略可。省略時の既定値は多くが 1)
- 終端文字 (final byte) が命令の種類を決める (`H` = 移動, `J` = 画面消去, `m` = 色/装飾 など)
- 引数の前に `?` が付く「プライベートモード」もある (`\x1b[?25l` = カーソル非表示)

```rust
fn main() {
    // \x1b[1m = 太字, \x1b[31m = 赤, \x1b[0m = リセット
    println!("普通 \x1b[1m太字\x1b[0m \x1b[31m赤\x1b[0m \x1b[1;32m太字の緑\x1b[0m");
    // エスケープシーケンスの中身を見てみる
    let s = "\x1b[31mred\x1b[0m";
    println!("{:?}", s);
    println!("{:?}", s.as_bytes());
}
```

`{:?}` で表示すると `\u{1b}[31mred\u{1b}[0m` のように見え、端末が解釈する前の姿がわかります。
テストではこの形で比較します。

## カーソル移動

座標は **1 始まり** で、`行;列` の順 (y が先!) です。プログラム内部では 0 始まりの `(x, y)` で
持つことが多いので、変換を忘れないようにしましょう。

| シーケンス | 意味 |
|---|---|
| `ESC [ row ; col H` | 絶対位置へ移動 (`ESC [ H` は左上) |
| `ESC [ n A` / `B` / `C` / `D` | 上 / 下 / 右 / 左 へ n 移動 |
| `ESC [ n G` | 同じ行の n 列目へ |
| `ESC [ s` / `ESC [ u` | カーソル位置の保存 / 復元 (`ESC 7` / `ESC 8` も同様) |
| `ESC [ 6 n` | カーソル位置の問い合わせ (端末が `ESC [ row ; col R` を stdin に返す) |

```rust
fn move_to(x: u16, y: u16) -> String {
    // 内部は 0 始まり (x, y)、端末は 1 始まり (row; col)
    format!("\x1b[{};{}H", y + 1, x + 1)
}

fn main() {
    assert_eq!(move_to(0, 0), "\x1b[1;1H");
    assert_eq!(move_to(4, 2), "\x1b[3;5H");
    // 同じ行の中で戻って上書きする (進捗表示などで使う)
    print!("progress: 10%");
    print!("\r"); // CR で行頭へ
    println!("progress: 100%");
    println!("{:?}", move_to(4, 2));
}
```

`\r` (キャリッジリターン) は行頭へ、`\n` (ラインフィード) は次の行へ移動する制御文字です。
通常の端末設定では `\n` を出すと自動的に `\r\n` に変換されますが、**raw モードではこの変換も
止まる** ので、TUI では改行に `\r\n` を書くか、毎回カーソルを明示的に移動させます。

## 消去

| シーケンス | 意味 |
|---|---|
| `ESC [ 2 J` | 画面全体を消去 (カーソルは動かない) |
| `ESC [ J` (= `0J`) | カーソルから画面末尾まで消去 |
| `ESC [ 2 K` | 現在行を全部消去 |
| `ESC [ K` (= `0K`) | カーソルから行末まで消去 |
| `ESC [ 3 J` | スクロールバック (履歴) も消去 (xterm 拡張) |

画面をクリアして左上から描き直すときは `"\x1b[2J\x1b[H"` がよく使われます。
ただし毎フレーム全消去するとちらつくので、TUI では「変わったセルだけ書き直す」
差分描画 (第22章) を行います。

## 色と装飾: SGR

`ESC [ ... m` は **SGR (Select Graphic Rendition)** と呼ばれ、以後に出力する文字の見た目を変えます。
複数の引数を `;` でまとめて指定できます (`\x1b[1;4;31m` = 太字 + 下線 + 赤)。

| 引数 | 意味 | 解除 |
|---|---|---|
| 0 | すべてリセット | - |
| 1 | 太字 | 22 |
| 2 | 薄く (dim) | 22 |
| 3 | イタリック | 23 |
| 4 | 下線 | 24 |
| 7 | 反転 (前景と背景を入れ替え) | 27 |
| 9 | 取り消し線 | 29 |

### 16 色

| 色 | 前景 | 背景 | 明るい前景 | 明るい背景 |
|---|---|---|---|---|
| 黒 | 30 | 40 | 90 | 100 |
| 赤 | 31 | 41 | 91 | 101 |
| 緑 | 32 | 42 | 92 | 102 |
| 黄 | 33 | 43 | 93 | 103 |
| 青 | 34 | 44 | 94 | 104 |
| マゼンタ | 35 | 45 | 95 | 105 |
| シアン | 36 | 46 | 96 | 106 |
| 白 | 37 | 47 | 97 | 107 |
| 既定色 | 39 | 49 | | |

実際にどんな色になるかは端末のテーマ次第です (ユーザーの配色に合わせられる利点がある)。

### 256 色と truecolor

- 256 色: 前景 `ESC [ 38 ; 5 ; n m`、背景 `ESC [ 48 ; 5 ; n m` (n = 0〜255)
  - 0〜15: 16 色と同じ / 16〜231: 6×6×6 の色立方体 (`16 + 36*r + 6*g + b`, 各 0〜5) / 232〜255: グレー 24 段階
- truecolor (24bit): 前景 `ESC [ 38 ; 2 ; r ; g ; b m`、背景 `ESC [ 48 ; 2 ; r ; g ; b m`
  - 対応端末は環境変数 `COLORTERM=truecolor` を設定していることが多い

```rust
fn main() {
    // 16 色
    for code in 30..=37 {
        print!("\x1b[{code}m██\x1b[0m");
    }
    println!();
    // 256 色の色立方体の一部
    for i in 16..52 {
        print!("\x1b[48;5;{i}m  ");
    }
    println!("\x1b[0m");
    // truecolor のグラデーション
    for i in 0..32 {
        let r = i * 8;
        print!("\x1b[48;2;{r};0;{}m ", 255 - r);
    }
    println!("\x1b[0m");
}
```

色の型を Rust の enum で表すと、TUI ライブラリの `Color` 型とほぼ同じ形になります。

```rust
#[derive(Clone, Copy)]
enum Color {
    Reset,
    Red,
    Green,
    Indexed(u8),
    Rgb(u8, u8, u8),
}

fn fg(c: Color) -> String {
    match c {
        Color::Reset => "\x1b[39m".to_string(),
        Color::Red => "\x1b[31m".to_string(),
        Color::Green => "\x1b[32m".to_string(),
        Color::Indexed(n) => format!("\x1b[38;5;{n}m"),
        Color::Rgb(r, g, b) => format!("\x1b[38;2;{r};{g};{b}m"),
    }
}

fn main() {
    for c in [Color::Red, Color::Green, Color::Indexed(208), Color::Rgb(100, 149, 237)] {
        println!("{}colored text{} {:?}", fg(c), fg(Color::Reset), fg(c));
    }
}
```

> 色を変えたら必ず最後に `\x1b[0m` などで戻しましょう。戻し忘れると、プログラム終了後の
> シェルのプロンプトまで色が付いたままになります。

## 代替スクリーンとカーソル表示

`vim` や `less` を終了すると、起動前の画面がそのまま戻ってきます。これは **代替スクリーン
(alternate screen)** を使っているからです。端末は通常の画面とは別に、もう 1 枚の画面を持っています。

| シーケンス | 意味 |
|---|---|
| `ESC [ ? 1049 h` | 代替スクリーンに切り替え (カーソル位置も保存) |
| `ESC [ ? 1049 l` | 通常スクリーンに戻る |
| `ESC [ ? 25 l` | カーソルを隠す |
| `ESC [ ? 25 h` | カーソルを表示する |
| `ESC [ ? 7 l` / `h` | 行末での自動折り返しを無効 / 有効 |
| `ESC [ ? 1000 h` 等 | マウスイベントの報告を有効化 (第19章で crossterm 経由で使う) |

`h` は set (有効化)、`l` は reset (無効化) と覚えます。

TUI アプリの典型的な起動・終了処理は次の通りです。

```
起動: raw モード ON → ESC[?1049h (代替スクリーン) → ESC[?25l (カーソル隠す) → ESC[2J (消去)
終了: ESC[?25h (カーソル表示) → ESC[?1049l (元の画面) → raw モード OFF
```

終了処理は **パニックしても必ず実行** しなければなりません。これを忘れると、ユーザーの端末は
カーソルが消えたまま・入力が表示されない状態で残ります (`reset` コマンドで直せますが不親切です)。
第18章・第19章で Drop ガードとパニックフックを使って保証します。

## 端末のサイズ

画面の幅と高さは、ioctl システムコール (`TIOCGWINSZ`) で取得します。標準ライブラリには
これがないので、`libc` クレートか crossterm の `terminal::size()` を使います (第18章・第19章)。
端末がリサイズされると、プロセスに `SIGWINCH` シグナルが送られます。

エスケープシーケンスだけで取得する裏技もあります。カーソルを `ESC[999;999H` で右下の端へ
動かして (はみ出した分は端で止まる)、`ESC[6n` で位置を問い合わせると、返ってきた座標が画面サイズです。

## 小さなライブラリを作る

ANSI シーケンスを関数としてまとめておくと、テストしやすく、読みやすくなります。

```rust
use std::fmt::Write as _;

struct Screen {
    out: String, // 1 フレーム分を貯めるバッファ
}

impl Screen {
    fn new() -> Self {
        Screen { out: String::new() }
    }
    fn move_to(&mut self, x: u16, y: u16) -> &mut Self {
        let _ = write!(self.out, "\x1b[{};{}H", y + 1, x + 1);
        self
    }
    fn fg256(&mut self, n: u8) -> &mut Self {
        let _ = write!(self.out, "\x1b[38;5;{n}m");
        self
    }
    fn text(&mut self, s: &str) -> &mut Self {
        self.out.push_str(s);
        self
    }
    fn reset(&mut self) -> &mut Self {
        self.out.push_str("\x1b[0m");
        self
    }
}

fn main() {
    let mut s = Screen::new();
    s.move_to(2, 0).fg256(196).text("Hello").reset();
    println!("{:?}", s.out);
    // 実際に表示してみる (画面を消さずに色だけ確認)
    println!("\x1b[38;5;196mHello\x1b[0m");
}
```

`std::fmt::Write` を使うと `String` に `write!` できます。`std::io::Write` と名前が同じなので、
`use std::fmt::Write as _;` のようにトレイトだけをインポートするのが定石です。

本番では `out` を 1 フレームごとに stdout へ `write_all` して `flush` します。この
「文字列を貯めて最後に 1 回書く」形が、第22章の自作フレームワークの原型になります。

## よくあるコンパイルエラーと読み方

**`error: unknown character escape: `e``**
→ C やシェルの `"\e[31m"` は Rust では使えません。`"\x1b[31m"` か `"\u{1b}[31m"` と書きます。

**`error[E0034]: multiple applicable items in scope`** (`write!` 周り)
→ `std::io::Write` と `std::fmt::Write` を両方 `use` しています。片方を `as _` でインポートするか、
使う側でどちらかに絞りましょう。

**`error: invalid format string: expected `}`, found ...`**
→ `format!` の中で `{` を文字として使うときは `{{` と書きます。ANSI 自体には `{` は出てきませんが、
シーケンスを組み立てるときに `{}` を書き間違えやすいので注意。

**色が付かずに `[31m` のように表示される**
→ ESC 文字が抜けています。`{:?}` で出力して `\u{1b}` が入っているか確認しましょう。
また、出力先が端末でない (パイプ) 場合はそもそも色を出さないのが作法です (第15章 `IsTerminal`)。

## まとめ

- 端末エミュレータとアプリは pty を挟んでバイトをやりとりしている
- `ESC [` で始まる CSI シーケンスで、カーソル・消去・色を制御する。座標は 1 始まりの `行;列`
- SGR (`...m`) で色と装飾。16 色 / 256 色 (`38;5;n`) / truecolor (`38;2;r;g;b`)
- 代替スクリーン `?1049h/l`、カーソル表示 `?25h/l`。終了時は必ず元に戻す
- シーケンスは `String` に貯めてから 1 回で書き出すと、速く、テストもしやすい
